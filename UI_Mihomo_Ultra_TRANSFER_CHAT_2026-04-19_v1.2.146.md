## Что вошло в v1.2.146
- поднят UI до `1.2.146`
- в **Host QoS** проблемные строки внутри diagnostic slice теперь сортируются по severity, а не как попало
- в **Host QoS** у каждой строки в активном diagnostic slice показывается короткая причина попадания: live traffic / no label / draft mismatch
- в **Traffic / Users** diagnostic slices теперь сортируют пользователей по релевантности текущей проблемы: blocked/limited first, выше usage, выше live traffic
- в **Traffic / Users** у каждой строки внутри активного diagnostic slice показывается короткая причина попадания: `Нет привязок`, `QoS без runtime-IP`, `{percent} лимита`, `Live: rate`
- контракт данных для **Home Assistant не менялся**: структура payload/export оставлена прежней
- обновлены transfer-файлы, snapshot памяти модели и правила workflow

## Что важно помнить
- Для этого проекта пользователь всегда ждёт: **архив релиза**, **commit message отдельно**, **команды для роутера отдельно**, **обновлённые docs**.
- В docs нужно поддерживать файл переноса в новый чат и фиксировать не только код, но и рабочие правила/формат ответов.
- Если меняется `router-agent`, нужно синхронизировать версию в `install.sh` и status API. В этом релизе agent не менялся.
- При работе с HA-интеграцией нельзя самовольно менять структуру экспортируемых данных без отдельного запроса.

## Что проверить после обновления
1. **Host → QoS**: при открытии live/unlabeled/pending slices строки должны идти в осмысленном порядке и показывать короткую причину попадания в срез.
2. **Traffic → Users**: missing devices / stored-only QoS / near-limit / active traffic должны открывать полный проблемный набор и сортировать строки по релевантности текущей проблемы.
3. У строк в активном diagnostic slice должны появляться поясняющие плашки: `Нет привязок`, `Нет runtime-IP`, `QoS без runtime-IP`, `{percent} лимита`, `Live: ...`.
4. Экспорт в HA и существующие метрики должны остаться без изменений.
