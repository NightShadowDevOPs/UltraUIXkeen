## Что вошло в v1.2.161
- Паттерн safe-паузы по скрытой вкладке расширен на несколько уже существующих operational-карточек.
- `Router → System`, `Router agent`, `Host QoS` и `Users QoS` теперь тоже не держат background polling, когда вкладка браузера скрыта.
- При возврате на вкладку эти карточки делают мягкий refresh и продолжают обычный polling.
- `router-agent` оставлен на `0.6.32`; HA/export контракт и структура данных не менялись.

## Что важно помнить дальше
- нельзя ломать автоматическую проверку SSL-сертификатов провайдеров
- обновление UI на роутере идёт через встроенный updater интерфейса, а не через `git pull`
- если меняется router-agent, нужно синхронизировать версию в `router-agent/install.sh`, status API, docs и HA handoff bundle
- любые следующие доработки раздела Трафик и Задачи делать осторожно: сначала runtime-безопасность, потом украшательства
- отдельно не ломать структуру данных от router-agent в Home Assistant через agent/handoff

## Что проверить после обновления
1. `Задачи → Живые логи`: при прокрутке блока логов за пределы экрана автообновление ставится на паузу.
2. `Router → System`, `Router agent`, `Host QoS`, `Users QoS`: при скрытии вкладки браузера их polling должен вставать на паузу.
3. При возврате на вкладку эти карточки должны проснуться без ручного перезахода.
4. Кнопка `Обновить` в блоке логов работает как раньше.
5. В `Обзор` диаграмма весов трафика остаётся живой и работает как раньше.
6. HA/export runtime и router-agent snapshot ведут себя как раньше.
7. Реальный трафик через роутер и QoS runtime не деградировали после обновления.

## Следующий логичный шаг
- после живой проверки `v1.2.160` + `v1.2.161` можно продолжать safe upstream review и брать только те изменения, которые снижают burst/load или лишние UI-перерисовки без риска для runtime.
- следующий безопасный кандидат: смотреть только на safe cherry-pick из upstream, которые уменьшают burst/load без новых постоянных polling-контуров и без изменений HA/export shape.
