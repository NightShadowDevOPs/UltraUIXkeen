# Request ledger — UI Mihomo / Ultra

Журнал устойчивых пользовательских запросов и решений по проекту. Это не сырой chat log, а нормализованный реестр того, что уже зафиксировано и должно учитываться в следующих релизах.

## Устойчивые правила формата релиза
1. В каждом релизе нужен архив.
2. Commit message даётся отдельно.
3. Команды для роутера даются отдельно.
4. В docs обязательно поддерживать файл переноса в новый чат.
5. Если меняется `router-agent`, нужно приложить отдельную команду его обновления.
6. В командах для роутера добавлять `clear`.

## Устойчивые технические решения
1. UI-проект живёт в репозитории `NightShadowDevOPs/UltraUIXkeen`.
2. Путь на роутере: `/opt/UltraUIXkeen`.
3. Обновление UI на роутере выполняется **через сам интерфейс UI**, а не через `git pull` как основной путь.
4. При изменении `router-agent` нужно синхронизировать версию в `install.sh` и в status API.
5. QoS и трафик вынесены в отдельный раздел **«Трафик»**.
6. Проверку SSL-сертификатов прокси-провайдеров трогать нельзя без отдельной команды пользователя.
7. При будущей редактуре `config.yaml` нужен fallback на эталонный рабочий конфиг.

## Зафиксированные пользовательские пожелания по развитию
1. Провести аудит структуры меню и разделов, потому что текущая IA перегружена.
2. Управление конфигом Mihomo вынести из `Settings` в отдельный раздел.
3. После стабилизации HA-контура продолжать развитие раздела «Трафик»: устройства, QoS, бейджи, иконки, устранение дублей.
4. Не перегружать роутер тяжёлыми аналитическими сценариями только ради Home Assistant.
5. Каждый шаг и каждый запрос на изменение отражать в документации проекта, а не только итоговые релизы.
